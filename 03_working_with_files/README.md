# Biological File Formats Overview

## 1. FASTA Format (.fasta, .fa, .fna, .faa)
- **Significance**: The universal standard for representing nucleotide (DNA/RNA) or amino acid (protein) sequences without per-base quality metrics.
- **Structure**: Header lines begin with `>` containing the sequence identifier and description, followed by one or more lines of raw sequence characters.
- **Primary Purpose**: Reference genomes, gene transcripts, protein databases (e.g., **UniProt**), target sequences for alignment (**BLAST**), and multiple sequence alignments (**MSA**).

## 2. FASTQ Format (.fastq, .fq)
- **Significance**: The primary raw output format generated by High-Throughput Sequencing (HTS) platforms (e.g., Illumina, PacBio, Oxford Nanopore).
- **Structure**: Iterative 4-line blocks consisting of `@Header`, `Sequence`, `+` separator, and `ASCII-encoded Phred Quality Scores`.
- **Primary Purpose**: Quality control (FastQC), base quality trimming, adapter removal, and alignment input.

## 3. CSV / TSV Formats (.csv, .tsv, .txt)
- **Significance**: Standard structured tabular data formats storing matrix-based biological datasets.
- **Structure**: Delimiter-separated fields (commas for `.csv`, tabs for `.tsv`) with optional header rows.
- **Primary Purpose**: Storing sample metadata, RNA-seq read counts, DESeq2 differential expression tables, and compound activity profiles.

## 4. BED Format (.bed)
- **Significance**: A lightweight, tab-delimited format designed for defining genomic regions and feature intervals.
- **Coordinate System**: 0-based, half-open `[start, end)`. The start position is 0-indexed, while the end position is non-inclusive.
- **Structure**: Requires 3 mandatory columns (`chrom`, `chromStart`, `chromEnd`) and up to 9 additional optional columns (name, score, strand, thickStart, itemRgb, blockCount, etc.).
- **Primary Purpose**: Representing ChIP-seq peaks, ATAC-seq open chromatin regions, exon coordinates, custom genome browser tracks, and interval operations (e.g., `bedtools`).

## 5. GFF3 and GTF Formats (.gff3, .gtf)
- **Significance**: Standard 9-column tab-delimited formats for comprehensive hierarchical gene models and transcript annotations.
- **Coordinate System**: 1-based, fully inclusive `[start, end]`. Both start and end positions are included in the feature length.
- **Structure**: Columns 1–8 hold positional metadata (`seqid`, `source`, `type`, `start`, `end`, `score`, `strand`, `phase`), while Column 9 contains key-value attribute metadata.
- **Primary Purpose**: Structural genome annotation, RNA-seq quantification (e.g., `featureCounts`, `HTSeq`), gene model visualization, and splice variant profiling.

## 6. SAM and BAM Formats (.sam, .bam)
- Significance: The core format for storing short or long sequencing reads mapped against a reference genome.
  - **SAM (Sequence Alignment/Map)**: Human-readable, tab-delimited text format.
  - **BAM (Binary Alignment/Map)**: BGZF-compressed binary equivalent of SAM, indexed for rapid coordinate-based spatial retrieval (`.bam.bai`).
- **Coordinate System:** 1-based inclusive mapping coordinates.
- **Structure**: Optional header block (prefixed with `@`) followed by 11 mandatory tab-delimited fields per read (including `QNAME`, `FLAG`, `RNAME`, `POS`, `MAPQ`, `CIGAR`, `SEQ`, and `QUAL`).
- Primary Purpose: Read alignment storage (BWA, Bowtie2, STAR), depth of coverage calculation, structural variant detection, and input for genomic variant callers.


## 7. VCF and BCF Formats (.vcf, .bcf)
- **Significance**: The standardized format for storing genomic variations, including Single Nucleotide Polymorphisms (SNPs), Insertions/Deletions (Indels), and Structural Variants (SVs).
  - **VCF** (Variant Call Format): Text format with header metadata lines (prefixed with `##`).
  - **BCF** (Binary Call Format): Compressed binary representation indexed for rapid spatial lookup (`.bcf.csi`).
- **Coordinate System**: 1-based inclusive reference position.
- **Structure**: Contains 8 mandatory site columns (`CHROM`, `POS`, `ID`, `REF`, `ALT`, `QUAL`, `FILTER`, `INFO`), followed by FORMAT specification and per-sample genotype fields.
- **Primary Purpose**: Variant discovery, population genetics, genome-wide association studies (GWAS), disease mutation filtering, and clinical genomics pipelines.

## Coordinate System Conversion Rules
Converting between 1-based inclusive formats (GFF3, GTF, SAM, VCF) and 0-based half-open formats (BED) requires shifting the start coordinate:
- 1-based to 0-based (e.g., GFF3/GTF $\rightarrow$ BED):
  - $$\text{Start}_{\text{BED}} = \text{Start}_{\text{GFF}} - 1$$
  - $$\text{End}_{\text{BED}} = \text{End}_{\text{GFF}}$$
- 0-based to 1-based (e.g., BED $\rightarrow$ GFF3/GTF):
  - $$\text{Start}_{\text{GFF}} = \text{Start}_{\text{BED}} + 1$$
  - $$\text{End}_{\text{GFF}} = \text{End}_{\text{BED}}$$
- Feature Length Calculation:
  - BED (0-based half-open): $\text{Length} = \text{End} - \text{Start}$
  - GFF3/GTF (1-based inclusive): $\text{Length} = \text{End} - \text{Start} + 1$
