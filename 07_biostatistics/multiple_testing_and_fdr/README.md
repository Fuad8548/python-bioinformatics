# 1. The Basics of Multiple Testing & FDR

**The Crisis: The Multiple Testing Problem**
When we run a statistical test on a single gene with a significance threshold of $\(\alpha = 0.05\)$, we accept a 5% risk of a false positive (a Type I error). That sounds safe.
However, in genomics, we are not testing one gene; we are testing thousands simultaneously. If we test 1,000 genes where the treatment actually does absolutely nothing (all null hypotheses are true), a 5% false positive rate means:
$\(\text{Expected\ False\ Positives}=1,000\times 0.05=50\text{\ genes}\)$
We will find 50 "statistically significant" genes that are pure background noise. If we scale this up to the human genome (~20,000 genes), we get 1,000 false positives.

## The Solution: Controlling FDR vs. FWER
To fix this, we have two methodologies:
1. Bonferroni Correction (Controls FWER): This aims for zero false positives across the entire experiment by dividing $\(\alpha \)$ by the number of tests ($\(0.05 / 20,000\)$). This is far too strict for biology; it throws away all your real discoveries (high Type II error rate).
2. Benjamini-Hochberg / BH (Controls FDR): Instead of ensuring zero false positives, BH allows a few, but keeps them under a strict ratio. The False Discovery Rate (FDR) is the expected proportion of false positives among the genes we declare significant. If we set an FDR (q-value) threshold of 0.05 and find 100 significant genes, we accept that roughly 5 of them might be false discoveries, but 95 are real.


## The Benjamini-Hochberg (BH) Algorithm
The algorithm works like a dynamic filter:
1. Rank: Sort all our m raw p-values from smallest to largest (i = 1, 2,...., m).
2. Calculate: For each rank i, calculate a critical value: $\(p_{(i)} \le \frac{i}{m} \times \alpha\)$.
3. Find the Cutoff: Find the largest rank i where the raw p-value is less than or equal to its critical value. Everything at that rank and below is declared significant.
4. Monotonicity Adjustment: The formula $\(q_{(i)} = p_{(i)} \times \frac{m}{i}\)$ can sometimes create out-of-order steps. The algorithm forces the adjusted p-values (q-values) to stay ordered by sweeping backwards.


# 2. Step-by-Step Codebase Breakdown
## 2.1: The Correction Engine
```python
def adjust_pvalues_bh(pvalues: list[float], alpha: float = 0.05) -> pd.DataFrame:
    p_arr = np.array(pvalues)
    reject, qvalues, _, _ = multipletests(p_arr, alpha=alpha, method="fdr_bh")
```
- `multipletests()` is the heavy lifter.
- `method="fdr_bh"` tells it to execute the Benjamini-Hochberg False Discovery Rate procedure.
- It returns four elements. We capture the first two: `reject` (a Boolean array of True/False based on our `alpha`) and `qvalues` (the newly calculated, adjusted FDR values).

## 2.2: Simulating the Genomic Data

null_pvals = np.random.uniform(0, 1, 950)
signal_pvals = np.random.exponential(scale=0.01, size=50)
signal_pvals = np.clip(signal_pvals, 1e-6, 0.05)

The script mimics a real experiment with 1,000 genes:
- 950 Null Genes: `np.random.uniform(0, 1)` creates a flat, even distribution of p-values between 0 and 1. This represents genes where the drug did nothing—their p-values are random noise.
- 50 True Signal Genes: `np.random.exponential` creates heavily skewed, tiny p-values close to 0. This simulates genes that genuinely responded to the drug.

### Why did "Significant" drop to 0?
We passed 50 true signal genes into the simulation, yet the BH correction wiped every single one of them out, leaving us with 0 significant genes. Why?
1. **The Noise Drowned the Signal**: We have 950 completely dead genes and only 50 real ones. Because the mathematical penalty $\(\frac{m}{i}\)$ depends heavily on the total number of tests (m=1000), a small pool of true discoveries gets penalized severely if their raw p-values aren't incredibly tiny.
2. The `np.random.exponential(scale=0.01)` Factor: While an exponential distribution with a scale of 0.01 yields small numbers, many of those 50 values will hover around 0.01, 0.02, or 0.04. They are small, but they are not small enough to withstand being multiplied by $\(\frac{1000}{i}\)$.
3. Uncorrected Illusion: Out of the 102 uncorrected genes, roughly 50 were pure mathematical illusions (false positives generated by the 950 uniform null genes, since $\(950 \times 0.05 \approx 48\)$). The BH procedure recognized that the signal was too weak to distinguish from this massive wall of random noise, so it protected us from publishing false discoveries by setting the final count to 0.

### How to Fix the Code to See BH in Action
To give the true signal genes enough strength to survive the correction, their raw p-values need to be much closer to zero. If we change the signal simulation scale from 0.01 to 0.001:
```python
signal_pvals = np.random.exponential(scale=0.001, size=50) # Stronger biological signal
```
